# 游戏助手任务窗口

从游戏助手打开「任务」。原任务目录与 jobdaily 提供标题，服务器依据真实角色的
原事件位、道具与有序 NPC 分支发布状态和当前步骤。此窗口是本项目助手，
不宣称 2.5 原客户端已有任务日志。道具窗口仅显示道具，旧任务日志入口移除。

贝壳按原 SP 位选择花与贝壳的交付方向。完成任务仍列出；可重做标记表示原链
存在 CLEAN 分支，实际可重做还须满足当前条件。奖励仍持有时不能重领，助手
不自动丢奖励或清事件位。伐木交斧后 END18 不代表木材已交付，推荐书、许可证
和木材继续决定后续阶段；原档位从有效分支取，不向玩家列出所有原脚本分支。

每个已验证地点提供「瞬移」与「瞬移到该地图并走过去」。客户端先下载地图包，
再请求服务器解析任务步骤；服务器检查当前活动、组队和原地图碰撞、NPC占格、
原传送门及连通性。客户端收到权威目标后加载地图，入口模式复用现有旅行导航。
NPC 抵达后使用原任务对白，奖励仍由服务器核验，窗口不直接改角色数据。
采木目标来自已导入的原区域，抵达时不自动发起 NPC 对话。

手动移动、取消、战斗、断线及迟到下载/回复须终止过期行程。远程客户端不依赖
本机 backend。验证采用真实原目录、GameSession、Backend 和端口0 WebSocket；
headless 验证交互与状态，不能证明最终渲染像素。

## 原交付任务自动执行

「自动做任务」开放贝壳、药草与成人仪式。药草按原领取、医生取药、交回三步执行，预下载3110与20105；无原CLEAN，完成不能重做。博士捕宠与伐木未开放自动。客户端先准备对应任务地图，
服务器选择真实可执行分支、安全传送，并等待发起设备确认地图位置，再执行
REQUEST 的 YES、ACCEPT 的 YES 与结果 OK；不会误点重复 REQUEST 的取消。
重做只在原 CLEAN 已满足时执行，不自动丢弃玩家奖励。

停止保留已经同步保存的交换，清除待确认对白；手动移动、其他活动、组队变化
及发起连接断线停止运行。服务器可信连接标识区分同角色的不同设备，其他设备
断线不会停止发起者；同角色仍可从另一设备手动停止。等待位置确认有超时。
允许服务器保存交付意图并在重启后依据已保存旗标、道具重新选择原分支，不恢复旧对白token。吃药或丢药后再启动会重新去医生取药；每笔交易仍通过原保存边界，保存失败回滚并停止。自动确认与传送是项目助手便利。

## 助手列表与网格

游戏助手页头可切换列表／网格。`viewer_pref("helper_view")` 仅保存该设备的
布局，默认列表，不进角色存档或服务器自动化设置。各入口独立 SVG 线图标在
运行时缓存，无新增下载包；说明保留为提示。网格按窗口调整列数，超出内容
可滚动、翻页，键盘焦点和手柄目标保持可达。战斗期间各入口沿用原可用规则。


成人仪式 event4/job1 的三阶段读取原审判、差使分支。两种传送和自动任务初始
落点为项目便利，明确绕过原入口等级30；原接取LV>0和十五空格条件仍由服务器
检查。自动任务在10204通道内逐格走到差使再返回，沿途随机遇敌使用现自动战斗，
结算成功后继续；通用不遇敌开关也适用于这条路线。低血量自动停机、失败、
手动停止、移位、组队、断线时任务停止，战斗可交回玩家。启用重启恢复后，成人
未完单人战斗恢复同一敌群/回合/RNG，再继续任务；奖励提交以原交易存档为准。
