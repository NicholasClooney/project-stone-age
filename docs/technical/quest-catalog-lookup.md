# Exact quest NPC lookup cost

The stage-two integration at9af2257, with the current main imported catalog cloned locally (297 source NPCs,2,791,432 bytes; SHA256 `0c0fbe8ccf0b8480528d5a8711f858aaba4a33b8200a501ae762b1b1c810b8f5`), exceeded the420-second water transaction budget. A temporary instrumented complete run took479.88s real,473.86s user CPU and3.35s system CPU. It made63,860 `active_npcs()` calls costing351.349s inclusive,9,495 navigation-key calls costing132.885s, and175 quest snapshots costing341.800s. These nested totals must not be added. Route pathfinding and legitimate-arrival movement checks were small; the guard battle took18ms. This is evidence of repeated projection/copy cost, not an assertion that host load caused a flaky test.

`active_npc(id)` uses the same ordered per-record projection as `active_npcs()`, including enabled-event branches, personal movement/hidden state, unspawned regional actors, TimeMan visuals, golden services, the jug shop and independent Charm services. It preserves first-active duplicate-ID behavior and fresh deep copies. `original_quests.npc_by_id()` still refreshes personal state before lookup. There is no shared mutable result cache, cross-profile cache or delayed invalidation.

`quest_catalog_lookup_test` retains the original full-array algorithm as an independent oracle. It checks every actual source and service ID, absent IDs, water disabled while adult gates remain, personal move/hide, regional birth, shared event12 event subsets, TimeMan visual changes, duplicate ordering and nested-return isolation between catalogs. Its same-catalog298-ID comparison initially measured1,790,759us for the original lookup versus11,364us for the single-record lookup. No task rule, reward/RNG operation, source catalog or save schema changes.

Temporary profiler wrappers and the one-off snapshot probe are removed from delivered code. The source/oracle-only dependency a60609a is included locally as an equivalent commit after9af2257. Subsequent navigation-key work and complete bounded suite verification are recorded separately.

## Navigation key projection

The second change retains Golden Bui's exact `[map_id]` result outside its protected maps, returning before reading the catalog. Wind retains its original four-field key, including personal NPC version, region and ordered eligibility. It uses `active_npcs_on_map()` to filter source records by their effective personal map before deep-copy projection. Public map 100, Munde 11107 and personally relocated NPCs remain candidates. Neither change caches mutable dictionaries or removes near-talk invalidation.

`quest_navigation_projection_test` compares both keys with independent copies of their original algorithms. It covers every actual catalog map, absent maps, independent services, public/Munde/wind/water maps, personal version and moved/hidden overrides. An actual source wind gate and six-floor walk establish legitimate arrival before checking near/far talk changes; the test does not grant arrival marks.

The baseline and optimized water runs retain 4,660 position reports, 9,495 navigation keys, 175 helper snapshots and 51 route path searches. Complete execution falls from 479.88s to 250.916s (248.832s user CPU, 1.465s system CPU), within the unchanged 420s budget. Navigation-key inclusive time falls from 132.885s to 4.166s: wind from 64.760s to 1.461s, Golden Bui from 63.959s to 0.015826s. Route/guard time falls from 254,745ms to 117,414ms; actual guard battle time remains 18ms. Remaining full catalog projections are measured rather than attributed to load. Timings include temporary profiler overhead; all profiler wrappers are removed from the delivered files.

## Ordinary branch copies

Ordinary NPC projection previously deep-copied every source branch into a record, discarded the copied branch array, then deep-copied enabled branches again. The third change shallow-copies only the outer ordinary record, replaces `branches` on that new dictionary, then deep-copies all remaining fields. Enabled branches are appended in the unchanged original order and with the unchanged filter. TimeMan, Golden Bui and jug special handlers keep their complete-record path. No shared source dictionary or nested array is modified.

The independent original-algorithm oracle now recursively mutates every nested returned dictionary and array and verifies both source equality and a fresh result after each state scenario. The same actual catalog measured 568,425us for 100 original projections versus 431,205us after removing redundant copies; each ordinary projection avoids 556 discarded source-branch copies. This is a local same-process comparison, not a wall-time guarantee.

The stage-only brothers/golden run retained as a regression artifact reached the authoritative messenger loot assertion but timed out at 300.016s (298.049s user CPU, 1.478s system CPU). Its fixed 300s budget was not extended. An attempted arrival run failed before test initialization in Godot's log-directory startup because sandbox access was unavailable; that attempt is not a suite runtime measurement. Subsequent bounded runs use the authorized isolated test directory.

With all three changes, the complete bounded water run takes 200.276s (198.589s user CPU, 1.216s system CPU), with 0 failures and no script errors. It still executes 4,660 position reports, 9,495 navigation keys, 175 helper snapshots, 51 route searches and 12,868 single-ID lookups. Full catalog calls remain 31,996, while their inclusive cost drops from the stage-only 168.123s to 119.597s. The change reduces copying work, not route or transaction coverage.

The bounded brothers/golden suite completes in 296.706s (294.615s user CPU, 1.612s system CPU), with all original route, reward-alternative, reload and LAN assertions passing. Its unchanged 300s budget leaves only 3.294s measured headroom on this run; this is a passing result with limited margin, not evidence of ample capacity.

The final water-arrival suite completes in 152.628s (151.019s user CPU, 1.055s system CPU), within its unchanged 300s budget, with 0 failures and no script errors. Both original lake roots, project-placement refusal, true guards, material-gate save failure/retry, approved OR synthesis and actual END46 exchange remain covered. All three runs are serial, headless and use isolated test saves. No full suite or live server operation was performed.

## Geometry occupancy projection

A fourth one-line change replaces only `geometric_destination`'s full NPC projection with the existing exact map projection. The existing map predicate, full `world.set_quest_catalog` refresh, resident loop, links, map data, safe-cell checks and authorization remain untouched. It does not change helper steps or introduce a cache. The separate harvest-step fix is outside this patch and must be retained when integrating.

`quest_geometry_projection_test` runs geometry with a catalog subclass returning the original full active array at the projection seam as its old-behavior oracle. It compares both modes and the entire world resident array across twelve actual source maps, an unknown map, personal movement into/out of the destination, hidden occupants, regional birth and disabled water events. Explicit assertions show an occupied safe cell is excluded and moving/hiding its occupant restores the original destination. This tests observable geometry rather than duplicating the new map-projection implementation.

The fourth-change brothers run completes in 290.024s (286.916s user CPU, 1.845s system CPU), 0 failures and no script errors, within the unchanged 300s limit. Compared with the third-change run it saves 6.682s and leaves 9.976s measured headroom; margin remains limited. Snapshots stay at 266, position reports at 4,981 and navigation keys at 10,228. Full catalog calls fall from 48,472 to 44,354, exactly 4,118 fewer; map projection calls rise from 10,228 to 14,346. Geometry runs 4,118 times and full world refresh remains 4,126 times. Snapshot inclusive time changes 284.649→277.775s; full projection inclusive time 178.527→169.066s. These nested measurements are not additive, and single-snapshot sampling did not predict the whole-suite gain. All temporary instrumentation is removed.

## Source-specific entry projection

The fifth change adds uncached `active_npcs_by_source(script)`: immutable source metadata is filtered before the shared active projection, retaining source order, duplicates, services and fresh deep copies. Only the loop input in twelve `entry` functions changes: dragon, dream, four jewels, Goya, Jan, Katan, Marju, miner, Munde, Saton, earth and wind. Their original source/map/ID/branch/first-match predicates and every `steps` body stay unchanged.

`quest_catalog_source_test` reuses the independent pre-optimization full-array oracle for every actual script plus empty/missing source strings, services, personal move/hide/birth, disabled events and shared event12 activation. It recursively mutates returned arrays/dictionaries and checks source and subsequent results remain unchanged. Each of the twelve entries is compared against full-array input, including absent branch indexes, Dream map filters, Wind ID filters and duplicate IDs deliberately inserted for their actual source scripts on different maps. Three complete representative helper snapshots compare equal to the full-array-input oracle (public location, personal hidden relocation, disabled water).

Only short equivalence and microbenchmark work runs while main performs its parallel full suite. The next complete brothers test retains the original 300s limit and all assertions and waits for the coordinator's low-contention window. Microbenchmark results are not extrapolated to whole-suite savings; representative snapshot timings include cache warm-up differences.
