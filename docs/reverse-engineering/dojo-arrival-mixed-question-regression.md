# Dojo arrival: mixed question regression

The full187 failure begins after the actual portal to floor841; the first quiz and all five original entry routes pass. The two-answer assertion fails, then the three janken assertions fail because the quiz did not open the next side. Rerun188 passes, but that is not evidence of a load-dependent timeout.

The test's old `answer()` selected `state.answer_choice` whenever present. `golden_bui_service.gd:68–74` copies the previous question state before setting the current `answer_type`. A text question (type4) installs `answer_text` and public `submit/cancel` choices but may still contain the previous question's `answer_choice`. The actual reply implementation at lines133–136 requires `submit`; a retained numeric choice is rejected as `无效选择。`. Neither this service path nor its original `gmsv/npc/npc_quiz.c` has an answer wall-clock deadline. The timestamp in the router token supplies uniqueness, not expiry. There is no asynchronous wait between the two synchronous Backend commands.

A single-process controlled reproduction uses the unchanged original841 question pool and RNG seed1. It selects question73/type2 then question38/type4. After the first correct answer, the authority state is index1/correct1/type4, retained `answer_choice="2"`, with the real text prompt requesting `submit`. The old helper sends `2`, receives the explicit rejection, and reproduces all four full187 failures without changing load, sleeps or deadlines. Historical full187 does not record its random question IDs; this reproduction establishes the concrete failing path rather than asserting its exact historical seed.

The fix changes only this test's answer helper to dispatch from the current `answer_type`. It fixes seed1 before the real two-answer interaction and verifies both actual question states, the public text input and submit choice, successful closure, the exact original841(18,15) Warp and retained arrival. It continues walking through the original portal to842 and running the existing no-ticket janken transaction. Entry/quiz save failures and stale token assertions remain. There are no production, policy, shared driver, source data, RNG algorithm or timeout changes, and no direct grants.

Validation uses one deterministic failing run of the old helper and one targeted run of the fixed full `quest_arrival_dojo_test`.
