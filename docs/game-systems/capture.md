# 捕捉判定（本地参考实现）

依据本地 `references/chenmingbiao-stone-age/gmsv/battle/battle_event.c` 的 `BATTLE_CaptureCheck`（3091–3160）。这是所固定社区源码的行为，不代表所有历史版本完全一致。

## 分数与随机判定

```text
分数 = [10 − 当前HP² / 最大HP
       + 人物等级/2 − 目标等级/2
       + 人物敏捷/15 − 目标敏捷/15
       + 物种捕获参数 + 人物幸运]
       × 人物魅力 / 50
       + 本次捕获加成 + 睡眠加成
```

- 按参考代码的单精度浮点运算顺序计算，不先把等级差或敏捷差取整。最大HP不大于0时按1处理。
- 睡眠中的目标加15；分数最高截到99，不把负分数强行改成正数。
- 抽整数1…100，只有 **随机数 < 分数** 才成功。因此分数99实际成功率98%；分数50实际49%；分数50.5实际50%。
- 正常目标须允许捕获，且目标等级不能高于人物等级5级。开发者全宠捕捉绕过不在此轮范围。
- 原公式没有60%血量硬门槛；满血可能成功，低血量也可能失败。助手默认59%是何时开始尝试的策略，失败后继续按原有自动战斗策略尝试。
- 捕获加成在一次尝试后清零，包括失败。物种参数取原表 `E_T_GET`；导入数据字段历史名称为 `capture_resistance`，它是直接相加的参数，不能按名称取反或把负值丢掉。缺失时明确拒绝，不补造概率。

## 人物魅力与幸运

新人物魅力60，依据 `gmsv/char/char.c:274`。幸运依据同文件 `CHAR_setLuck`（4005–4040）：随机整数0…99对应幸运1…5，概率40%／30%／20%／7%／3%。

参考调用发生在登录（`CHAR_login`，1210行）：只有相对上次记录跨了石器日／年才更新，不是在每次捕获或战斗时重抽。`gmsv/handletime.c` 以912771809为历法起点，5400秒一日，100日一年；头文件旧注释不作为周期依据。重实现按新建／读取角色处理登录，并保存幸运和更新时间；同一游戏日读档保留幸运。

当前实现使用基础魅力／幸运及已提供的捕获加成、睡眠状态。旧存档缺魅力时补60，不从当前等级推断历史魅力。升级、死亡、宠物逃跑导致的完整魅力变化，装备魅力／幸运修正、施加睡眠的完整技能、特殊物种所需捕获道具及其消耗暂缓；不能把本轮说成已还原整个捕获相关系统。

## 验证原则

用独立原生C公式结果核对浮点边界；测试严格随机比较、最大成功率、血量、等级门槛、正负物种参数、睡眠和一次性加成。另测幸运概率分段、石器日／年边界和读档保留，并回归正常捕获结算与自动培养流程。测试只写临时存档，后台静音执行。
