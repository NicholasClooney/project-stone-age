# 宠物币：离线工作量证明实验

一个只在本机运行的学习实验：每挖出一个区块，就诞生一只宠物，宠物的全部特征都由区块哈希决定。没有网络，没有真正的链，不发布任何东西，也不改动游戏代码。只用 Python 3 标准库。

## 它演示了什么

- **哈希代替随机数。** `seed = SHA-256(prev_hash || target || timestamp || miner_id || nonce)`，再用 `SHA-256(seed || counter)` 展开成字节流，用拒绝采样抽取无偏整数。物种（按稀有度权重：蓝人龙70%、金虎20%、红暴龙8%、机暴2%）、四项资质偏移、10个出生点，以及2到120级每一级的成长抽样，全部来自这条流。所以宠物在出块那一刻，Lv.120属性就已经确定，任何人都能在约0.17毫秒内重算验证。
  - 讨论里的公式是 `SHA-256(prev || miner_id || nonce)`；这里把 target 和时间戳也放进哈希，这样出块后它们也不能被改。
- **规则照搬游戏。** 出生和升级按 `client/server/progression.gd` 的 `species_actor`、`grow_pet`、`derived()` 移植：资质各 `randi(-2..2)`，10个出生点，成长档由物种权重和按 [100,95,90,85,80,0] 划分，每级10个随机点加一次倍率 `[450+档*20, +50]`，整数截断。满档蓝人龙 Lv1→120 的攻防敏三围合均值为 **616.79**，与 `docs/game-systems/pet-quality.md` 的 616.8 一致（测试里用3000只样本、容差0.3检查）。
- **比特币式挖矿。** `int(hash) < target` 才算有效块，每10块按实际用时向每块2秒重新调整 target（单次最多放大或缩小4倍）。
- **另一种规则：只有达到品质门槛的宠物才算数**（`--rule quality`）。难度只能在资质总档的台阶之间跳，见下文。
- **验证。** `verify_chain` 重算链接、target、调整、工作量证明和每只宠物；改动宠物、nonce、prev_hash 或 target 都会被拒绝。
- **身份绑定。** 矿工 ID 是一个字符串，代替公钥哈希。把别人的 nonce 抄过来换成自己的 ID，哈希完全不同，宠物也不同，而且几乎一定不满足难度（`steal` 命令演示）。签名和转账都不在本实验范围内。

物种数值（初始值与四项权重）取自被忽略的 `client/assets/legacy/encounters/catalog.json`（原表 `gmsv/data/enemybase.txt`），直接写在代码里，所以新工作区不需要原版资源：蓝人龙92（29；27/36/16/20）、金虎194（25；19/29/18/29）、红暴龙303（27；23/37/20/25）、机暴304（帖拉所伊朵，28；23/35/25/21）。「机暴=304」按讨论采用，仓库文档里还没有核实这个对应。

## 怎么运行

```sh
cd experiments/pet-coin
python3 petcoin.py mine --blocks 20 --miner alice   # 挖矿，写入 chain.json
python3 petcoin.py verify                           # 全链重算
python3 petcoin.py show                             # 每块的宠物
python3 petcoin.py show --height 3                  # 单块详情
python3 petcoin.py steal --height 3 --miner eve     # 抄 nonce 换 ID
python3 petcoin.py --rule quality mine --blocks 20  # 品质门槛规则，写入 chain-quality.json
python3 petcoin.py bench                            # 哈希速率与稀有宠物期望次数
python3 petcoin.py ladder                           # 品质规则的难度台阶
python3 -m unittest test_petcoin                    # 测试
```

链文件已被本目录的 `.gitignore` 忽略。

哈希派生宠物的蒙特卡洛：物种比例 0.700/0.200/0.080/0.020 与设计一致；满档蓝人龙在100万个哈希中出现1118次（1/894，精确值1/893）。160万只满档蓝人龙：均值616.80，≥620约6.9%，≥624约1/8500，≥625约1/100000，最高626。这比文档的1/10500略重，仍在抽样误差量级内。红暴龙所有出生的Lv.120三围合均值609.8，前0.1%的门槛是≥652（因为取整，实际占0.127%）。

## 早筛：为什么安全性在 SHA-256，不在游戏公式

物种和资质来自扩展流最前面的6个字节。想刷稀有宠的矿工可以先算区块头哈希，再多算一个 SHA-256 看前几个字节，不合格就丢掉，完全不必跑119级成长。只有约1/893的候选需要0.17毫秒的完整推导，摊到每次尝试可以忽略。所以每次尝试的成本约等于两个哈希加一点比较（Python 里早筛比纯哈希慢约3倍，主要是解释器开销）。难度和防伪都靠 SHA-256；游戏公式只决定「挖到的是什么宠物」，不增加挖矿成本。

## 品质门槛规则的难度为什么很粗

`ladder` 的输出：按资质总档设门槛，从总档≥-8到≥+8只有17级。低端每升一级难度只变1.002倍到1.2倍，高端一步就是2倍、3倍、5倍；到满档（1/625）之后就没有下一级了，最高难度只有625次尝试，按本机速率不到1毫秒。再往上只能改用Lv.120三围合门槛，而满档蓝人龙的三围合台阶从≥622起每级跳4到8倍。目标规则的 target 是256位整数，可以调到任意倍数；品质规则只能在这些台阶间跳，出块时间没法平稳。实测里 `--rule quality` 每10块只能升一级，块几乎瞬间就出。

## 局限

- **不是货币。** 每只宠物都不一样，不可互换；它更像收藏品，不是可分割的币。
- **没有网络，没有共识。** 只有一个人在本机挖一条链，没有分叉选择、传播或节点。
- **小链的51%风险。** 算力小的链，任何人租点算力就能重写历史。
- **没有签名和转账。** 矿工 ID 只是字符串，谁都可以用；真正的所有权需要公钥签名。
- **石器时代的名字和美术不是我们的。** 公开发布任何东西都需要原创宠物和美术。
- **代币发行受监管。** 真要发行代币，涉及各地的金融和证券法规，这里完全不考虑。
- 时间戳只检查不倒退、不超前两小时，没有中位时间等规则。
